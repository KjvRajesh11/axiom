## 1. Research Question and Hypotheses
### Primary Research Question:
How do algorithmic transformation, compiler vectorization, explicit SIMD intrinsics (ARM NEON), and multithreaded scaling impact execution throughput, arithmetic intensity, and memory locality on modern Apple Silicon ARM64 architecture?

### Formal Testable Hypotheses:
- **[PROPOSED]** `[MEMORY_BOUND]` **HYP_MATMUL_IKJ_LOCALITY: Memory Locality**
  - *Statement:* Interchanging loops from i-j-k to i-k-j converts the inner loop access to matrices B and C from strided column traversal (stride 128 elements = 512 bytes) to unit-stride contiguous row traversal (stride 4 bytes), eliminating cache line thrashing.
  - *Uncertainty:* `LOW`
  - *Supporting Evidence:* Static inspection confirms B[k * N + j] has stride 1 along inner loop index j.; Row-major layout stores adjacent row elements in adjacent bytes on the same 128-byte cache line.
  - *Confirmation Rule:* Candidate achieves > 2.0x speedup over baseline at N >= 128.
- **[PROPOSED]** `[COMPUTE_BOUND]` **HYP_MATMUL_IKJ_SIMD: Auto-Vectorization**
  - *Statement:* Unit-stride access in the inner loop enables Clang/LLVM loop vectorizer to generate ARM64 NEON 128-bit vector fused multiply-add (fmla) instructions, processing 4 single-precision floats per cycle per execution pipeline.
  - *Uncertainty:* `LOW`
  - *Supporting Evidence:* Clang optimization remark confirmed: 'vectorized loop (vectorization width: 4, interleaved count: 4) [-Rpass=loop-vectorize]'.; Reference i-j-k explicitly missed vectorization: 'the cost-model indicates that vectorization is not beneficial'.
  - *Confirmation Rule:* Candidate GFLOP/s increases by > 3x compared to baseline.
- **[PROPOSED]** `[MEMORY_BOUND]` **HYP_MATMUL_CACHE_TILED: Cache Blocking**
  - *Statement:* Tiling matrices into 64x64 sub-blocks restricts the active working set to 3 * (64x64) * 4 bytes = 48 KB, fitting within the Apple M4 L1 Data Cache (64 KB). This prevents capacity cache evictions as N increases.
  - *Uncertainty:* `MEDIUM`
  - *Supporting Evidence:* Apple M4 L1d cache size is 65,536 bytes (64 KB).; For N >= 512, full matrices exceed L1d capacity (512x512 = 1 MB, exceeding L1d).
  - *Confirmation Rule:* Blocked candidate maintains throughput stability at large sizes (N >= 512).
- **[CONFIRMED]** `[COMPUTE_BOUND]` **HYP_MATMUL_ARM_NEON: Explicit SIMD**
  - *Statement:* Hand-written ARM NEON intrinsics using 4x4 register blocking keep 4 independent vector accumulators live in 128-bit NEON registers, hiding pipeline execution latency and saturating dual FMA pipelines.
  - *Uncertainty:* `LOW`
  - *Supporting Evidence:* Kernel uses vld1q_f32, vfmaq_f32, and vst1q_f32 directly from arm_neon.h.; Direct instruction control bypasses compiler heuristic register allocation.
  - *Confirmation Rule:* Explicit NEON candidate matches or outperforms auto-vectorized candidate without regressions.
  - *Empirical Outcome:* Confirmed by 11.72x measured speedup, consistent with 4-way NEON SIMD vectorization.
- **[PROPOSED]** `[COMPUTE_BOUND]` **HYP_MATMUL_MULTITHREADED: Multithreading**
  - *Statement:* Distributing matrix row blocks across independent CPU cores using C++20 concurrency delivers near-linear scaling when computation time exceeds thread creation and join latency.
  - *Uncertainty:* `LOW`
  - *Supporting Evidence:* Apple M4 features 10 CPU cores.; Row-block partitioning guarantees disjoint write sets with zero inter-thread locks.
  - *Confirmation Rule:* Candidate achieves > 2.0x speedup over single-threaded candidate for N >= 256.
- **[PROPOSED]** `[MEMORY_BOUND]` **HYP_MATMUL_CONTROLLED_REGRESSION: Controlled Regression**
  - *Statement:* Pathological j-k-i column-strided traversal on row-major matrices creates maximum spatial cache misses and instruction stalls, demonstrating that Axiom's decision engine correctly identifies regressions.
  - *Uncertainty:* `LOW`
  - *Supporting Evidence:* Column stride N * 4 bytes forces a new cache line read on every innermost iteration.; Inversion forces column strided write-backs to memory.
  - *Confirmation Rule:* Candidate exhibits > 2x latency degradation relative to baseline and is rejected.

## 4. Baseline Implementation
The reference implementation utilizes the canonical `i-j-k` triple nested loop structure:
```cpp
for (int i = 0; i < N; ++i) {
    for (int j = 0; j < N; ++j) {
        float sum = 0.0f;
        for (int k = 0; k < N; ++k) {
            sum += A[i * N + k] * B[k * N + j]; // Strided column access on B
        }
        C[i * N + j] = sum;
    }
}
```
- **Locality Characteristic:** In row-major layout, `B[k * N + j]` advances by `N * sizeof(float)` bytes each iteration.
- **Consequence:** Causes cache line misses on each step as N grows, and prevents SIMD vector packing.

## 5. Candidate Transformations
- **Loop Interchange (`interchanged`):** $i$-$k$-$j$ order, unit-stride contiguous row iteration, exposing vector registers.
- **Cache Blocking (`blocked`):** $64 \times 64$ sub-blocks tuned to Apple M4 64 KB L1 Data Cache.
- **Explicit ARM NEON (`neon`):** 4x4 register-blocked microkernel using `vfmaq_f32` intrinsics.
- **Multithreading (`multithreaded`):** C++20 `std::jthread` row-block partitioning across CPU cores.
- **Controlled Regression (`regressed`):** Intentionally unoptimized $j$-$k$-$i$ column-stride to test regression detection.
